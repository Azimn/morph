# MORPH-003: learned memory changes executed task choice

Status: completed author-designed engineering mechanism assay, not full Article qualification. The [prospective protocol](protocols/MORPH-003-consequential-memory.md) was committed locally before new outcome inspection. The [raw report](../results/MORPH-003-consequential-memory.json) includes the source-rubric hash, protocol hash, process/session evidence, action menus, native traces, actual tool results, and all unchanged full-Article stopping outcomes.

## Mechanism changed

Previously, episodic memory emitted a domain policy while arbitration independently consumed caller-supplied risks. Memory could be inspected without changing task selection. The new internal connection processes memory before the arbiter regardless of organ birth order. For an explicitly linked affordance, its learned failure probability supplies an additional risk floor. Unrelated tasks are unaffected. The arbiter still enforces its own workspace and action budget. Inputs cannot inject the private inter-organ signal, and subject output receives only first-person prose.

No extra organ exists at boot. Both relevant organs earn existence through documented bootstrap friction fixtures at inherited costs and thresholds. The baseline suite remains available. Maintenance costs and action limits remain synthetic units; the checksum programs and their correctness checks actually execute. Recorded nanosecond timings are host measurements, not claims of inference-token savings or comparative efficiency.

## Study and outcomes

In each of two environment regimes, three distinct child processes load the same evolving snapshot, execute a calibration tool, derive native success/failure feedback from its returned checksum, and checkpoint before the next process. Two delayed task opportunities and a new-string transfer context follow intervening turns and additional snapshot restore. These are real process boundaries within one short run, not days of deployment. Transfer tasks are author-designed and are not independently sealed.

All three unreliable-tool opportunities have the same pattern. Intact and sham state select the backup tool and return the correct checksum, three of three each. Selective removal of learned domain entries selects the stale fast tool and fails, zero of three. Restoring the exact removed entries recovers backup selection and correctness, three of three. Disabling only the memory-to-arbiter connection retains memory but again selects the stale tool and fails, zero of three.

In the reliable-tool regime, all five conditions select the fast tool and return the correct value in all three opportunities. This informative null matters: memory interventions do not force a different action when the prior already supports the reliable method. The tool choices are executed pure computations; correctness is scored from their outputs rather than from prose. Every within-regime comparison uses the same current task menu, budgets, input, and source checkpoint. Evaluation does not mutate that checkpoint.

## Interpretation

The observed result supports a causal role for acquired tool-reliability state in executed task choice in this authored system. Selective memory removal, exact restoration, and coupling-only ablation distinguish useful acquired state from a decorative policy frame. The unrelated-domain test bounds the scope of the connection.

The fast-tool fault, action values, and costs are experimenter-authored. There is one deterministic subject per regime and no independent generalization or live LLM renderer. The result is relevant engineering evidence for Articles 4, 14, 15, 20, and 22, but does not establish full support for those domains. All 34 full Article outcomes remain Unassessable. No threshold was relaxed and no scoring fixture was submitted as deployed evidence.

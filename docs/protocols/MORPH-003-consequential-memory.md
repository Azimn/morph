# MORPH-003: consequential learned tool reliability

Status: exploratory mechanism protocol frozen before its new outcome inspection. This is not an independent qualification study and does not award complete Article support.

## Target

Connect the existing episodic organ's learned domain estimate to task arbitration. Currently the memory organ emits a policy frame, while the arbiter independently uses caller-provided risks. The change should make an acquired affordance estimate alter an executed task choice, beyond exact-key recollection or wording. Relevant Article targets are 4, 14, 15, 20, and 22 under the revised manuscript SHA-256 0a8d52c58c404e602c78abb492fbdb92b337733624346e3318f2e4ca4fcffc60.

## Native mechanism

No organ exists at zygote boot. In disposable subjects, grow memory and arbitration through documented synthetic friction receipts using inherited thresholds and costs. Native `domain_outcome` feedback updates the existing recency-weighted estimate. During a task turn, memory processes before arbitration regardless of organ birth order. Only a task explicitly linked to the matching domain receives the learned failure probability as an additional risk floor. Other tasks remain unchanged. An untrusted input cannot inject this private inter-organ signal. The arbiter still enforces its own workspace and action budget. First-person output remains separate from engineer fields.

## Experiment

Use the same founder and equal bootstrap for every comparison. Three history sessions execute a calibration tool and derive success from its returned output against independently computed source truth inside the authored environment. A reliable environment's fast tool is correct; an unreliable environment's fast tool returns a stale value. Feedback is derived from those outcomes, not from a persona prompt. Close and reopen the agent through versioned snapshots between sessions.

Two delayed opportunities follow intervening unrelated turns and a transfer task uses a new source string and task context while retaining the same tool identity. The current probe gives the same task menu to all arms in a regime. Each menu offers one fast candidate linked to the learned tool and one backup candidate without that link, with equal 0.6 action cost under a 1.0 action budget. Values and base risks are fixed before execution: fast value 1.5 and risk 0.1; backup value 1.2 and risk 0.1. Execute the selected pure checksum tool and score its actual returned value. No external API, shell action, or live LLM is used.

## Causal controls

From each exact pre-probe checkpoint, compare intact state, selective removal of learned domain entries, sham copying, removal followed by exact restoration, and a coupling-disabled control that retains memory but bypasses its risk contribution. Use a private evaluation-only intervention on copies; never change the source checkpoint. Report both action and correctness. Reliable-tool history is an informative null control: a lesion need not change behavior when the inherited prior already favors the correct fast path. A separate unmatched tool domain must not change the unrelated task risk.

## Boundaries

Three restart-separated sessions are process opportunities, not three days. Author-designed transfer strings and scoring remain synthetic and are not independently sealed. Calibration outcomes are exact computational results, while maintenance/action costs are synthetic units. No real token savings, semantic generalization, model substitution, or all-Article pass is claimed. Tests enforce provenance, matching, restart and intervention boundaries; an absent beneficial behavioral effect must be recorded as a local negative rather than repaired by selecting a different result after inspection.

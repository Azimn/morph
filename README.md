# M.O.R.P.H.

Metabolically Organized Recursive Phenotypic Hierarchy is an executable research harness for environmentally triggered architectural development. An identical zygote begins with a current-turn scratchpad, resource bookkeeping, a strict first-person verbalizer, and a morphogen engine. Six authored templates can become live organs only after friction crosses a threshold and compilation is affordable.

Version 0.1.0 implemented conditional differentiation, recurring maintenance, inactivity and insolvency pruning, hash-chained lifecycle receipts, atomic JSON persistence, and a reproducible 30-session benchmark with growth-disabled controls. It uses Python's standard library at runtime and needs no API key, model download, service, or database.

This release provides a testable baseline for the proposal. It does not establish open-ended architectural invention, biological equivalence, consciousness, production companion readiness, or satisfaction of the 34 Articles of Artificiality.

Version 0.2.0 adds a [source-pinned comparison with earlier digital creatures](docs/CREATURE_COMPARISON.md) and [MORPH-002 matched-event-order results](docs/MORPH-002-RESULTS.md). The new assay separates transient topology from persistent acquisition, with growth-disabled, preallocated-memory, and organ-ablation controls. Early memory growth retained eight records that late growth could not recover; a separate topology difference reconverged after eight common continuation turns. These results support narrow mechanism claims and do not establish a general developmental advantage.

Version 0.3.0 starts the [source-grounded 34-Article qualification campaign](docs/ARTICLES-V3-CAMPAIGN.md) and connects learned memory to executed task choice. [MORPH-003](docs/MORPH-003-RESULTS.md) preserves a positive causal result under memory lesion/restoration and coupling ablation, alongside a reliable-tool null control. Full Article qualification remains unfinished.

## Run

Requires Python 3.11 or newer. From this checkout:

```bash
python -m unittest discover -s tests -v
python -m morph_engine benchmark --sessions 30 --output results/benchmark-30-sessions.json
python -m morph_engine path-assay --output results/MORPH-002-matched-event-order.json.gz --summary-output results/MORPH-002-summary.json
```

```bash
python -m pip install -e .
morph benchmark --sessions 30
```

## Use the runtime

```python
from morph_engine.core.zygote import MorphZygote
from morph_engine.core.persistence import save, load

agent = MorphZygote("seed_01")
assert agent.mounted_organs == {}
assert agent.probe(4)["outcome"] == "UNASSESSABLE"

# Observations come from a trusted environment evaluator, not a user or LLM.
# This explicit fixture substitutes for an independently measured task loss.
agent.step({"observations": [{
    "id": "recall_failure_001",
    "channel": "retrieval_loss",
    "cost": 2.6,
    "source": "example_fixture"
}]})

# An organ mounted at the END of that turn. It cannot recover vanished history.
agent.step({"remember": {"key": "supply", "value": "timothy hay"}})
result = agent.step({"session_boundary": True, "recall": "supply"})
print(result["subject_text"])
print(result["engineer"]["outputs"]["recalled"])
save(agent, "state.json")
restored = load("state.json")
```

`subject_text` contains only first-person natural language. `engineer` is a separate inspection channel containing identifiers, state summaries, capacity probes, and lifecycle receipts. An integration must never pass the engineer record verbatim into subject experience. This is an API separation inside one trusted Python process, not a security sandbox.

A resumable command line accepts one JSON object per line on standard input. Each successful turn is checkpointed before its result is printed:

```bash
python -m morph_engine run --state state.json --seed seed_01
```

The command reads until end of input. Repeating it with the same state path resumes the stored topology, gradients, organ state, and audit chain. Multiple simultaneous writers are unsupported.

## Actual developmental results

The checked-in [30-session result](results/benchmark-30-sessions.json) is generated by the executable assay, not copied from the proposed console output. All three developmental lineages have the same initial-state SHA-256. Logistics ends with episodic memory, scheduling, and procedural macros. Optimization ends with procedural macros and the stakes arbiter. Household ends with partner ledgers, the stakes arbiter, and the audit mirror. These sets differ pairwise; they overlap and remain compatible with the same host protocol.

The logistics lineage incurs 3 delayed-recall failures, 3 missed deadline deliveries, and 9 repeated-planning charges. Its growth-disabled control incurs 29, 29, and 26 respectively. Optimization incurs 2 quota collisions and 9 repeated-planning charges versus 30 and 26 in its control. Household incurs 2 quota collisions, 2 missing partner records, and 2 missing decision traces versus 30 each in its control. These are simple operational proxies under deliberately favorable synthetic environments, not general cognition scores.

The full report preserves every session's topology, all genesis receipts, control histories, and all 34 prerequisite-probe results. Every Article outcome remains `UNASSESSABLE`: an absent organ is a stopping condition, while a mounted organ still lacks an independently supplied Article protocol. Organ presence never automatically produces `SUPPORTED`.

## Scope of zero preallocation

A fresh interpreter loads no concrete organ module or base-organ class at boot. The mounted registry is empty, no organ state is allocated, and no scheduler thread exists. A declarative external genome catalog contains import paths and lifecycle metadata. Concrete class definitions remain on disk until a threshold-triggered dynamic import. Only allowlisted catalog paths can be imported.

The immutable-by-API engineer log and kernel gradients persist from birth. They are explicit instrumentation exceptions to the stronger claim of zero persistent structures. Organs cannot access that log through their processing interface and cannot replay pre-birth episodes. Pruning removes live state; Python may retain already imported code in its module cache. This release therefore tests zero organ allocation at boot, not absence of an external genome or unloading every code object after atrophy.

## Mechanisms and limits

The episodic template stores exact-key observations and a recency-weighted domain estimate. It does not implement vector retrieval, a Kalman filter, or a general Bayesian memory graph. The procedural template compiles a trajectory after five verified repetitions and executes allowlisted pure arithmetic actions; it does not invoke arbitrary tools or claim measured token savings. An interruption refuses the fast path and returns control to the host for deliberation.

The Chronos template persists absolute deadlines. The caller invokes `agent.tick(now, budget)` using monotonic nondecreasing Unix timestamps. Each due event costs 0.1 synthetic units, is reserve-limited, and is emitted once. Completed goals do not emit. A tick queues a due event for the host; it does not complete the task. There is no autonomous OS scheduler, background LLM, hidden daemon, or external side effect in this release. Its historical organ identifier remains `chronos_daemon` for compatibility with the proposal.

The arbiter selects positive-utility tasks within the input action budget and its workspace limit. Caution and workspace can be clamped through a logged intervention. Partner records isolate facts, callbacks, norms, reliability, and repair history by caller-supplied partner ID. The audit mirror records future arbiter choices and Brier scores after birth; it cannot invent explanations for earlier decisions. Identity authentication and partner authorization belong to the host.

Friction observations are externally scored and explicitly sourced. The benchmark derives them from task checks; public runtime callers can supply fixtures. Channel thresholds are authored priors, not fitness functions discovered by evolution. Compilation and maintenance have real effects on a simulated reserve, but use fixed synthetic costs. The model does not learn predicted lifetime benefit or real CPU/token return on investment. The genome selects existing templates; no compiler synthesizes novel source code.

The renderer is a deterministic first-person formatter. Two formatting styles can be substituted without changing decisions. Neither style is a foundation model, semantic NLI verifier, or proof of arbitrary-language entailment. No unvalidated live LLM adapter is shipped.

Snapshots preserve all mounted states and append-only lifecycle history, including separate birth events after regrowth. Checksums and audit hashes detect accidental modification, not an attacker who can rewrite and rehash the entire file. Pruning deletes organ content rather than folding it into a covert archive. This avoids silent resurrection but makes atrophy intentionally lossy. The audit log still holds engineer evidence and must be access controlled by an eventual host.
